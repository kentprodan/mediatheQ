# 0023. Baseline profile and macrobenchmarks in `:baselineprofile`

- Status: Accepted
- Date: 2026-10-26

## Context

Cold start and Library scrolling should not pay for JIT warm-up (#71). A baseline profile compiles their code ahead of
time; it has to be generated on a real device and measured before and after. The only device is the owner's daily
Pixel 9: connected test runs there used to uninstall the app with its sign-in, synced library and downloads.

## Decision

- A `:baselineprofile` module (`com.android.test`, the `androidx.baselineprofile` plugin, Benchmark 1.5.0,
  UiAutomator 2.4.0) holds the generator (cold start to Home, Library album grid and songs list flung) and the
  macrobenchmarks (cold start with and without the profile, frame timing of both lists). A small
  `mediatheq.android.test` convention plugin sets its SDK levels and toolchain.
- `:app` applies the plugin as consumer and ships `profileinstaller` 1.4.1. The profile is committed in
  `app/src/release/generated/baselineProfiles/`. No startup profile: it only feeds R8's DEX layout, and release builds are
  not minified.
- `:app` declares the `benchmarkRelease` and `nonMinifiedRelease` build types itself: debug-signed (there is no release
  key) and with `applicationIdSuffix = ".benchmark"`, so every device run uses a separate app and never touches the
  daily one.
- Device test runs leave the apps installed (`android.injected.androidTest.leaveApksInstalledAfterRun=true`).
- The generator signs the benchmark app in through onboarding when needed, from instrumentation arguments the owner
  keeps in `~/.gradle/gradle.properties` (outside the repository). It fails rather than skip the Library: a
  startup-only profile would look like a success.
- CI compiles the module (`:baselineprofile:assembleBenchmarkRelease`); generation and benchmarks run only on the phone.

## Consequences

- The profile is regenerated by hand after big changes to startup or the Library lists.
- The benchmark password passes as an instrumentation argument, visible in Gradle's `--info` output of a run.
- The app's texts are English only, so the generator finds controls by text; translations would need test tags first.
